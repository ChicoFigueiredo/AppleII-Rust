## Seções por área

### 1. Saturn 128K

Caminho completo seguido: `settings.toml` (`[slots.N] card="Saturn128K" banks=4`) → `Settings` (`card.rs:284`) → `Settings::to_machine_config` (`machine.rs:64`) → `MachineConfig.slots[N] = Some(CardKind::Saturn128K)` → `LanguageCards::new` (`language_card.rs:116`, `SATURN_BANKS = 8` fixo) → `LcKind::Saturn { banks: 8 }` → `save_lc_card` (`apple2.rs:257`, grava `Num Saturn Banks: 0x08`) → `parse_lc_card` (lê N, mas `lib.rs:312` recria `CardKind::Saturn128K` sem N).

O primeiro elo (TOML ↔ Settings) preserva `banks`; o segundo (Settings → MachineConfig) o descarta. O comportamento diverge do C++: num Saturn de 64 K, selecionar o banco 5–8 (`$C0nC–F`) fixa em total−1 (`LanguageCard.cpp:424-430`); aqui o banco 5 é um banco real e distinto.

Passos para reproduzir:

```
cargo test -p apple2-config --test audit_saturn_banks -- --include-ignored
cargo test -p apple2-savestate --test audit_saturn_state -- --include-ignored
```

Saída esperada hoje: `machine_config_carries_saturn_bank_count` falha com `left: 8, right: 4`; `four_and_eight_banks_behave_differently` falha (`left: 0, right: 119`); `saturn_with_four_banks_keeps_its_size_through_load` falha (`Some(8)` vs `Some(4)`). O caso de 8 bancos passa (`eight_banks_work_through_settings`, `eight_bank_saturn_round_trips`).

### 3. CPU

- #1360 confere (052). O porte de `TestCPU6502.cpp` (GH#264/271/278/282/292/1257 e tabela de ciclos, 6502 e 65C02, com e sem page-cross) e a suíte funcional de Klaus Dormann (`klaus.rs`) passam; `extended_cmos` está `#[ignore]` porque o AppleWin não implementa BBR/BBS/RMB/SMB (consistente com o oráculo).
- BRK/IRQ/RESET conferem (053). NMI é divergência (054).
- Não foi feito diff de traço contra o AppleWin (não há binário oráculo disponível): primeiro opcode divergente, PC/A/X/Y/SP/P/ciclos por instrução continuam UNVERIFIED para os 256 opcodes ilegais não cobertos pelo `TestCPU6502.cpp`.

### 4. Floating bus / sincronismo (HU-0103)

Existe cobertura de raster (051). **Oráculo proposto** para os valores de byte:

1. Compilar o AppleWin no SHA `a8f0d1d` com o frontend Linux/SDL (`source/frontends`) em modo headless, ou chamar `NTSC_VideoGetScannerAddress()` + `MemReadFloatingBus()` por uma pequena harness C++ ligada a `NTSC.cpp`/`Memory.cpp`.
2. Para cada (modelo, padrão de vídeo, chaves TEXT/MIXED/HIRES/PAGE2/80STORE/RAMRD, ciclo-do-quadro), executar um `LDA $C0E0` posicionado com precisão por uma esteira de NOPs (o mesmo `lda_at` de `video_scanner.rs`), gravar o par (ciclo, byte lido) em CSV e versionar o CSV com SHA-256 como Fixture.
3. O teste Rust relê o CSV e compara bit a bit. Com isso 050 passa a ter decisão baseada em dados.

### 5. Disco (Disk II, WOZ, NIB, DSK) e HDD/SmartPort

- Flush ao desligar o motor, eject, sair e proteção contra escrita: PASS (032). WOZ malformado, bombas e traversal: PASS (035, 036).
- **Perdas de escrita:** ApplySettings e LoadState (030, 031), kill por sinal (034), contêiner comprimido (033).
- A gravação **não** sobrescreve o original de forma atômica: imagens simples são escritas no lugar por `FileStore::write_at` (igual ao AppleWin); `.gz`/`.zip` são truncados e regravados (033).
- Escrita pendente ao fechar o programa: tratada em `CloseRequested`/`Drop` via `Command::Shutdown` → `disks.flush` (`emu.rs:645-649`).
- HDD/SmartPort: bloco gravado é write-through no store (`hdd.rs:279-282`); boot ProDOS em SmartPort e bloco, leitura/escrita de bloco, erros e `STATUS` têm teste (`apple2-storage/tests/hdd.rs`); limite de 32 MB + cabeçalho 2MG. Não há fixture `v2/HDD-32MB.aws.yaml` (BLOCKED) nem teste de queda no meio de uma escrita de bloco.
- Troca de imagem: `insert_disk`/`eject_disk`/`swap_disks` descarregam a trilha anterior (`disk2.rs:299-346,398-403`); o contrato "o que vale na hora e o que reinicia" (HU-0302) não está especificado: `ApplySettings` reconstrói a máquina inteira (power-cycle, perde RAM) — ver 030.

### 6. Save-state

- Gravação não atômica (022); loader robusto a truncamento e valores errados (011), exceto 010; Unicode/espaço/`#`/`\` OK (021), UNC não (020); RGB (023) e impressora (024) não restauram; corpus real (026) e `Cycles This Frame` (060).
- O panic de 010 só aparece em debug (`overflow-checks`); em `--release` a multiplicação dá a volta e o resultado depende de `len`: para valores gigantes a alocação aborta o processo.
- YAML malformado nunca causou panic nos testes de truncamento/mutação (erro descritivo `Save-state parser error: ... @ linha:coluna`). Observação: `strip_comment` (`yaml.rs:181-196`) não trata `\"` dentro de aspas, de modo que `"a\" # b"` é cortado no `#` (sem panic; P3 não numerado).

Passos para reproduzir 010, 060 e 020/022:

```

cargo test -p apple2-savestate --test audit_cycles_this_frame -- --include-ignored
cargo test -p applewin --test audit_persistence -- --include-ignored
```

### 7. Configuração (registro/INI)

- A tabela `registry_map.rs` cobre todos os `REGVALUE_*` de `Common.h`; o importador lê todos os que têm destino. Perde-se: o `CPU Type` explícito 65C02 e o padrão 65C02 (040), nome de cartão desconhecido (silencioso, 041) e qualquer chave fora de `Common.h` (o AppleWin 1.32 grava mais valores por cartão em seções `Slot N`; só os de `Common.h` foram comparados).
- Chaves lidas só indiretamente (formatadas com `format!`): `Joystick{0,1} Emu Type[ v3]`, `Joystick N Emulation`, `AY Socket 0..3`, `SSI263 Socket 0..1`, `Last Harddisk Image 1..8`.
